# Автономный виртуальный CEX/DEX Paper

Запуск по живым рыночным данным с виртуальным капиталом. Настоящий кошелёк,
баланс ETH/USDT, allowance, подпись и операции перевода не требуются.

## Режимы

- `reference`: LONG/SHORT только фьючерса CEX. DEX задаёт ориентир для входа.
  Это направленная позиция, не нейтральный арбитраж. DEX газ не начисляется,
  поскольку DEX-операция не моделируется. Комиссии CEX, spread стакана,
  safety buffer и произошедший funding входят в NET.
- `paired`: виртуальная покупка токена за USDT на DEX и шорт фьючерса CEX.
  Выход продаёт виртуальные токены и закрывает шорт. Считаются обе цены DEX,
  gas обоих обменов и комиссии CEX. Продажа отсутствующего DEX-инвентаря
  не поддерживается: обратная DEX SELL / CEX LONG требует отдельной модели
  заранее выделенного токенового инвентаря.

В EVM источник DEX — индикативный 0x price, а не firm-транзакция.
Solana работает только в `reference` через Jupiter V2 quote-only: запросы без
адреса кошелька, подписи и `/execute`. Парная Solana-модель не включена, поскольку
здесь не проверяются газ, токеновые расширения и фактическое исполнение обмена.
Размер котировки соответствует маршруту. Количество контракта форматируется
по native precision/minimum и проверяется по свежему стакану. Цены DEX
уменьшаются на явный slippage haircut; неизвестные gas/tax блокируют парный
вход. USDT в этой модели оценивается в 1 USD. Токеновые decimals, контракт и
сопоставление токен/CEX в маршруте — явные допущения исследовательской модели,
не сертификат кошелька и не проверка пригодности токена для LIVE. Для Solana
ориентир котируется в USDC; USDC и USDT условно оцениваются в 1 USD, риск
отклонения стейблкоинов от доллара этой моделью не проверяется.

Маршрут задаёт notional и лимит CEX до $30. Парная модель резервирует DEX cash,
верхний CEX notional и $2 на расходы; reference — CEX notional и $2.
Минимальный резерв $12, плечо в распределении капитала не применяется.
Капитал и резервы других модулей учитываются при новом входе. Одновременно
открывается одна виртуальная CEX/DEX-позиция. Дневной риск общий с Paper.
Выходы: NET capture, trailing, NET stop и time stop. Неполный funding удерживает
резерв до сверки. Потеря DEX-ориентира не мешает CEX-only модели оценить выход
по риску/времени/NET; парной модели обязательно нужна обратная DEX-котировка.

## Windows

Остановить бот Ctrl+C, затем из папки проекта:

```powershell
.\.venv\Scripts\python.exe -m app.configure_virtual_paper --mode reference
.\.venv\Scripts\python.exe -m pytest -q
.\.venv\Scripts\python.exe -m app.main
```

Помощник сохраняет резервную копию `.env`, выключает корневой LIVE и DEX LIVE,
включает виртуальный режим. Reference по умолчанию запрашивает $30 notional,
чтобы размер не ограничивался прежними $5. Точные minimum/precision всё равно
проверяются и могут блокировать вход. `--notional 10` меняет виртуальный размер.
Ключи, капитал, база и прежние настройки маршрутов
не удаляются. Начальный маршрут — только Ethereum WETH / Bybit. `--mode paired`
меняет тип исследовательского эксперимента. Нельзя менять режим с открытой
позицией: её исходный маршрут должен оставаться в watchlist до закрытия.

Для нескольких маршрутов нужен JSON-файл и `--routes-file watchlist.json`.
Его структура совпадает с `DEX_VIRTUAL_ROUTES_JSON`. Каждая запись содержит
chain_id, stable, asset, stable_decimals, asset_decimals, base, cex_venue,
cex_symbol, native_symbol, native_decimals, mode и notional_usd.
Вторая приватная API-пара не обязательна: при её отсутствии ставка CEX берётся
из публичной metadata и помечается `PUBLIC_RATE_ASSUMPTION`.

## Расширенный список монет и Solana

Получить API-ключ в https://developers.jup.ag/portal и добавить локально в `.env`:

```dotenv
JUPITER_API_KEY=свой_ключ
DEX_VIRTUAL_SCAN_INTERVAL_SEC=5
```

Бот остановлен. Затем:

```powershell
.\.venv\Scripts\python.exe -m app.build_virtual_watchlist --preset channel --venues bybit --apply
.\.venv\Scripts\python.exe -m app.main
```

Помощник сохраняет существующие маршруты и добавляет подходящие Solana пары.
Начальные адреса SOL/JUP и GP/OTC/BATON/MASKSOL явно заданы. Адреса последних
четырёх взяты из предоставленных пользователем сигналов; это не LIVE-сертификат.
Он проверяет metadata точного mint, decimals, символ, активный линейный USDT
фьючерс и котировку Jupiter в обе стороны. По одному тикеру токен не выбирается.
Scaled-контракты вроде 1000TOKEN не сопоставляются с TOKEN автоматически.
Отсутствующий на Bybit фьючерс или недоступный маршрут пропускается с причиной.
Включение монеты не означает положительный NET или гарантию входа.

`virtual_watchlist_report.json` содержит маршруты и причины пропусков. Для
повторной сборки задать `--output virtual_watchlist_report_2.json`. Без `--apply`
создаётся только отчёт. `--preset core` проверяет SOL/JUP; `--seeds-file seeds.json`
принимает словарь `{"TICKER":"точный mint"}`. Начальная сумма новых reference
маршрутов $20, изменить через `--notional` (1–30). До 32 маршрутов всего.

Если нужны публичные MEXC котировки, можно явно задать `--venues bybit,mexc`
(обе биржи должны быть в EXCHANGES). Приватный ключ MEXC не нужен, комиссия
будет публичным допущением. Это не подключает торговый аккаунт MEXC.

Виртуальный DEX цикл делает одну проверку маршрута за проход, по кругу. Пауза
по умолчанию 5 секунд **после** обработки, а не обещание обновлять каждую монету
раз в 5 секунд: фактический срок зависит от списка и времени API. Jupiter запросы
ограничены одним в секунду, после 429 действует пауза 30 секунд. Открытая позиция
проверяется в каждом проходе. Остальные стратегии сохраняют прежний интервал.
Автоматического чтения Telegram и поиска произвольных токенов нет.

## Где смотреть

Главное меню → DEX, либо Позиции → CEX/DEX Paper. Переключатель DEX в
«Стратегиях» теперь открывает реальный статус модуля вместо устаревшего alert.
В интерфейсе видны виртуальные закрытия, итоговый NET, свободный капитал,
направление и причины отказа. Дневник observations остаётся общим; подробные
позиции/оценки/решения экспортируются на отдельных листах `DEX virtual ...`.
Состояние, резерв и PNL восстанавливаются из SQLite при перезапуске.

Результаты не включаются в firm DEX OOS/stress/account acceptance. Модель не
подтверждает фактические fills, доступность шорта, очередь/частичные fills,
исполнение DEX-транзакции или будущую прибыль. Прогноз funding не зачисляется.
Неопределённость данных сохраняется в истории, а не превращается в нулевые расходы.

Оставить Windows включённым, с интернетом, без сна. PowerShell должен работать.
Бот входит только при положительном NET-потенциале после расходов; отсутствие
входов — возможный результат наблюдения. Режим не принуждает открывать сделки.
