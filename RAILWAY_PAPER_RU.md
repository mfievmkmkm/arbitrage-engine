# Новый виртуальный эксперимент на Railway с телефона

## Два режима в одном боте

Для чтения канала без авторизации добавить
`DEX_CHANNEL_PUBLIC_READER_ENABLED=true`. Бот читает публичную страницу
https://t.me/s/MexcDexSpreadTracker без аккаунта, сессии и cookies, раз в 5 секунд
при включённой стратегии «Канал → MEXC». Публикация веб-превью может запаздывать.
Посты старше 90 секунд, Aligned, дубли и неизвестные точные маршруты пропускаются.
Статус доступности страницы виден в сравнении, принятые и пропущенные посты
в отдельном экспорте решений канала. Если публичное превью закрыто, изменилось
или заблокировано, входы по нему не выполняются; Bybit и выходы продолжают
работать. Пересылки остаются запасным способом. TG_API_ID/HASH/SESSION не нужны.

Актуальный вариант сравнения: один сервис, один BOT_TOKEN, один Volume и
два независимых портфеля. Добавить `DEX_DUAL_PAPER_ENABLED=true`.
Оставить `DEX_VIRTUAL_PAPER_ENABLED=true` и все LIVE-флаги false.
Для сохранения обычных стратегий установить старые отдельные настройки
`DEX_REFERENCE_FOCUS=false`, `DEX_CHANNEL_SIGNALS_ONLY=false`, удалить
`DEX_VIRTUAL_ENTRY_VENUES` (или оставить пустой). Эти ограничения теперь
задаются внутри каждого нового режима, не общими переменными процесса.

В «Стратегиях» появляются «Канал → MEXC» и «Автопоиск → Bybit».
Изначально новые входы обоих выключены; включить каждый кнопкой.
У каждого свой стартовый виртуальный баланс $50, целевой notional $20,
отдельные сделки, резервы, NET, статистика и дневной лимит потерь $2.50
(день UTC). Выходы продолжаются при выключении стратегии. При неподходящем
нативном размере биржи вход пропускается, сумма не увеличивается скрыто.
Пересланные свежие сигналы идут только в MEXC-портфель; Bybit ищет сам.
Используются существующие проверенные reference-маршруты, неизвестные токены
автоматически не подключаются. Остальные стратегии и старая история доступны.

В «Стратегиях» и «DEX → Paper» показывается сравнение. Экспорт содержит
отдельные листы DEX channel и DEX Bybit. Их виртуальные $50 не складываются
с общим капиталом старых стратегий. Истории и балансы сохраняются в SQLite;
после принятого входа один и тот же сигнал повторно не используется даже
после перезапуска. Убыточный маршрут блокируется на 10 минут.

Одинаковый капитал и правила риска не означают одинаковые рынки: канал
MEXC и собственный Bybit-сканер могут торговать разными токенами. Показанная
просадка считается по закрытым сделкам; открытый NET показан отдельно.
Обе новые модели reference направленные, без DEX-хеджа; прибыль не гарантирована.
Для двух режимов внутри одного бота второй сервис создавать не нужно.

Код подготовлен; реальный сервис нужно создать в своём Railway аккаунте.
Trial — кредит на использование, не гарантия 30 дней непрерывной работы.
Нужен Full Trial для доступа к биржам; на Limited Trial сеть ограничена.

1. Railway → New Project → Deploy from GitHub repo → `mfievmkmkm/arbitrage-engine`.
2. В Source выбрать ветку `phase-2-discovery` и последнюю согласованную ревизию.
   Если репозиторий не виден, проверить доступ GitHub integration к этому репо.
3. Добавить Volume, подключить к сервису бота, Mount Path **`/data`**.
4. В Variables → Raw Editor добавить значения ниже, заменив placeholders.

```dotenv
BOT_TOKEN=свой_токен
ADMIN_ID=свой_числовой_id
ZEROX_API_KEY=свой_ключ_0x
JUPITER_API_KEY=свой_ключ_Jupiter
EXCHANGES=bybit,mexc
PAPER_CAPITAL_USD=50
LIVE_ENABLED=false
LIVE_ENTRY_ENABLED=false
DEX_LIVE_ENABLED=false
DEX_VIRTUAL_PAPER_ENABLED=true
PAPER_SERVER_FRESH_START=true
DEX_VIRTUAL_WATCHLIST_PRESET=channel
DEX_VIRTUAL_SCAN_INTERVAL_SEC=5
BOOK_HISTORY_MAX_ROWS=20000
BOOK_HISTORY_HOURS=24
```

Не добавлять вручную RAILWAY_VOLUME_MOUNT_PATH: его задаёт настоящий Volume.
DB_PATH и JSON маршрутов вручную не нужны: entrypoint использует `/data/paper`.
При наличии уже сохранённой базы она не сбрасывается, даже с fresh-флагом true.
Если папка данных непустая, но базы нет, новый старт откажется затирать состояние.

BYBIT_API_KEY и BYBIT_API_SECRET необязательны. Без них комиссии CEX — публичное
допущение; с read-only ключом Bybit — прочитанные аккаунтные ставки. Ключ MEXC
для этого эксперимента не требуется. Приватный ключ кошелька не нужен.

Если Jupiter ключ пока недоступен, не добавлять пустой placeholder и поставить
DEX_VIRTUAL_WATCHLIST_PRESET=none: будет только Ethereum WETH/Bybit. Для него
ZEROX_API_KEY обязателен. Для Solana вернуть channel и добавить Jupiter ключ.

5. В Settings → Deploy указать Start Command:
   `python -m app.railway_paper_server`. Не назначать pre-deploy и HTTP healthcheck:
   Volume появляется во время запуска, а бот не предоставляет HTTP сервер.
   Serverless/Sleep выключить. Один экземпляр сервиса; домен не требуется.
6. Deploy. В логах первый раз появится NEW virtual experiment, затем результат
   сборки доступных маршрутов и запуск polling. При перезапуске база и список
   маршрутов сохранятся. Секреты в логах не печатаются.
7. После первого успешного запуска поменять PAPER_SERVER_FRESH_START=false.
   Это защищает от создания новой базы, если Volume позже случайно отсоединят.
8. Telegram → DEX → Paper → Обновить: проверить возраст последней проверки,
   число маршрутов и причины отказов. Старый Windows-бот должен быть остановлен.

Jupiter запросы ограничены AMM роутером Metis через официальный excludeRouters.
Проверяются routePlan, min-out, заданный slippage и price impact; другие типы
котировок не преобразуются в подтверждённое исполнение.

Сборка списка при первом старте проверяет точные mint и публичные CEX markets,
пишет причины пропусков и сохраняет найденные маршруты на Volume. При следующих
стартах повторно не меняет токены/decimals открытых позиций. Если все котировки
Solana отклонены, журнал сообщает причины и продолжает уже настроенные маршруты.
Для явной повторной сборки добавить DEX_VIRTUAL_WATCHLIST_REVISION=2 (при следующем
обновлении списка — другое значение). Старые маршруты сохраняются, новые только
добавляются после проверок. Ошибочная refresh-попытка не помечается успешной.

На Trial следить за RAM, расходом кредитов и размером Volume (0.5 ГБ). Ограничение
истории стаканов не ограничивает весь журнал: позиции/решения/marks продолжают
накапливаться. Выгружать дневник и делать backup до окончания пробного периода.
После удаления Volume история не восстанавливается из репозитория.

Документация: https://docs.railway.com/volumes и https://docs.railway.com/pricing/free-trial
## Отдельный эксперимент по сигналам канала

Раздел ниже описывает прежний одиночный режим. Для двух одновременных
режимов использовать DEX_DUAL_PAPER_ENABLED и кнопки в Стратегиях выше.

В Variables задать `DEX_REFERENCE_FOCUS=true` и `DEX_CHANNEL_SIGNALS_ONLY=true`,
затем Deploy. Требуются `DEX_VIRTUAL_PAPER_ENABLED=true` и все LIVE-флаги false.
Новые входы остальных стратегий отключаются; существующие позиции продолжают
проверяться и закрываться, история и общий виртуальный капитал сохраняются.

Администратор пересылает исходный LONG?/SHORT? пост из @MexcDexSpreadTracker
в личный чат бота стандартной пересылкой Telegram. Принимаются только посты
возрастом до 90 секунд с точной сетью, адресом и существующим проверенным
MEXC reference-маршрутом. Отчёты Aligned, копии текста, скриншоты и неизвестные
токены не запускают вход. Бот сам канал не читает. Приоритет сканирования
получают принятые свежие сигналы. Котировки из поста не используются как fills.

Перед входом проверяются реальные свежие публичные стаканы и DEX-котировки,
совпадение направления, bid/ask до 0.75%, моделируемые расходы немедленного
обратного выхода до 0.75% notional, потенциальный NET не меньше $0.10,
1% notional и двойных немедленных расходов. Две последовательные пригодные
проверки с интервалом 2–60 секунд обязательны. Это стартовые ограничения
эксперимента, не статистически оптимизированная стратегия и не гарантия прибыли.
После убыточного закрытия маршрут блокируется на 10 минут; блокировка
сохраняется на Volume. Закрытый сигнал удаляется и не переиспользуется.

Для автономного собственного сканера оставить `DEX_REFERENCE_FOCUS=true`,
а `DEX_CHANNEL_SIGNALS_ONLY=false`. В этом варианте пересылки не требуются,
но эксперименты уже не ограничены опубликованными сигналами канала.
