# Исправления по выгрузке 20 октября 2026, 17:33 Екатеринбург

Исходный файл: arbitrage_compact_audit (9)(1).zip. Последние 5000 кандидатов:
1620 KYBER_FILTERED_LIQUIDITY, 490 неподтверждённых идентичностей,
476 сбоев симуляции и 213 HTTP404 проверки токена. Это ограниченная выборка,
не статистика всех рынков и не доказательство упущенной прибыли.

## Изменения

* Kyber PAPER больше не требует прямой stable/asset pool. Разрешены составные
  маршруты поддерживаемых Uniswap/Pancake V2/V3, максимум 3 перехода на путь,
  4 пути и 6 переходов суммарно. Запрос single-path ограничивает стоимость проверок.
* Сначала проверяется непрерывность всех путей, начальный/конечный контракт,
  отсутствие циклов, формат адреса пула и поддержка протокола. Затем каждый
  токен проверяется в каждом своём фактическом пуле, включая промежуточные.
  Любой неизвестный/ненулевой налог, ограничение или неподдерживаемый протокол
  отклоняет маршрут. Нельзя использовать безопасность конечного токена для
  разрешения непроверенного промежуточного. Никаких build/approve/send запросов.
* После медленной симуляции — один новый запрос цены через общий rate limiter,
  с повторной проверкой фактически возвращённого маршрута. Старое доказательство
  чужого пула не разрешает новый маршрут. Старые цены не получают новый timestamp.
* Обнаруженный honeypot, неизвестный результат, высокий/неизвестный риск и
  сбой симуляции имеют разные причины. Сохраняются публичный scope, HTTP status,
  время и категория simulationError; непроверенный текст ответа не сохраняется.
  Отрицательный кеш сохраняет эти сведения, а не только ValueError.
* B сохраняет расчёт покупки/продажи, комиссий, funding/base/return переводов,
  gas, остатка, обычного NET, safety и стресс-NET. Каждый числовой отказ содержит
  значение/границы. Резерв 3% явно помечен как сценарий риска, не комиссия.
  Используется расчёт конкретного кандидата, а не изменяемый last_economics
  соседней параллельной проверки.
* В B добавлены чтение contractAddress/contract в обоих форматах metadata,
  подробности несовпадения и отказов по минимальным/максимальным размерам.
  Контракт нельзя подтвердить только совпавшим тикером.
* Один повтор REST spot-стакана при PUBLIC_BOOK_STALE. Возраст/порог
  сохраняются также для фьючерсного recovery-стакана. Старые данные не допускаются.
* B повторяет предварительную проверку один раз после устаревания котировок
  из-за длительного preflight; все сети, балансы и риск проверяются заново.
* Telegram больше не называет отсутствие составного маршрута отсутствием
  прямого пула и не обозначает любой сбой безопасности только как комиссию.

## Ограничения, которые исправление кода не отменяет

HTTP404, симуляция и внешняя ликвидность могут оставаться недоступными.
Другие протоколы/сети требуют отдельного адаптера доказательств; небезопасный
маршрут не получает разрешение из-за расширения поиска.
Нужен MEXC read-only API для подтверждённых transfer metadata; он не создаётся
из публичных котировок. DEX SELL без inventory/borrow остаётся запрещённым.
Параметры риска и комиссии пользователя не уменьшаются. История, балансы и
открытые позиции не очищаются. LIVE выключен.

Новые тесты используют явно контролируемые котировки, включая промежуточный
налог, смену пула после requote, HTTP404 и запись отказа B. Полные жизненные
циклы, убыточная продажа после перевода, partial fills и restart покрываются
существующими интеграционными тестами. Архив не содержит полного тика данных
для восстановления всех упущенных исполнений: их нельзя выдать за сделки.
